# Executive Summary

The Agent Client Protocol (ACP) enables any editor/IDE to interact with any coding agent via a standardized JSON-RPC interface. We examined ACP support in five popular agentic harnesses/CLIs: **OpenAI Codex CLI**, **Cursor CLI**, **Grok Build CLI**, **Anthropic Claude Code**, and **Google Antigravity CLI**. Our analysis shows:

- **Codex CLI (OpenAI)**: No native ACP mode, but the community-maintained [codex‑acp](https://github.com/agentclientprotocol/codex-acp) adapter provides full ACP support. It implements most ACP features (text prompts, images, code edits, shell commands, permissions, subagents, etc.), uses **stdio JSON-RPC** transport, and supports authentication via ChatGPT login or API keys. The CLI command `codex-acp` (via npm) starts the ACP server. Detailed environment variables (e.g. `CODEX_API_KEY`, `NO_BROWSER`) configure auth and models. Release notes and commits are tracked in the agentclientprotocol repo.

- **Cursor CLI**: Officially supports ACP. Running `agent acp` launches a stdio JSON-RPC server. Cursor implements ACP v1 and offers rich features: file read/write, shell execution, permission requests, and even custom extensions (e.g. `/cursor/ask_question`, `/cursor/create_plan` to ask the user questions or get plan approvals). It advertises a `cursor_login` auth method; users can pre-authenticate via `agent login`, an API key (`--api-key`), or token flags. Client configuration is minimal (Cursor uses `~/.cursor` for MCP servers, etc.). One known limitation: team-level MCP servers (from Cursor’s web dashboard) are *not* supported in ACP mode. Integration is straightforward: spawn the CLI with `agent acp` in the project directory and connect via any ACP client (e.g. Zed, Neovim, JetBrains).

- **Grok Build CLI (SpaceXAI)**: Fully open-source and ACP-ready. The command `grok agent stdio` starts an ACP server (JSON-RPC over stdio). It supports protocol v1 and implements all the usual endpoints (initialize, session/new, session/prompt, etc.). Authentication can be via interactive login (`grok login`) or by setting the `XAI_API_KEY` environment variable. It supports streaming updates (`session/update`) and all standard ACP features (file edits, shell commands, permissions, etc.). Config files live in `~/.grok` (often no manual config needed beyond login). Example invocation: 
  ```bash
  grok login          # authenticate (opens browser or set XAI_API_KEY)
  grok agent stdio    # starts ACP server on stdin/stdout
  ``` 
  The client then sends `initialize` and `session/new` requests; Grok responds with incremental text via `session/update` notifications. Grok’s only limitation is lack of a stable ACP v2 (it uses v1) and any Beta-v2 features.  

- **Anthropic Claude Code**: ACP support is provided via the *Claude Agent SDK* and third-party adapters. The Python package **`claude-code-acp`** (and a TypeScript counterpart) acts as an ACP agent server. Running `claude-code-acp` (after installing it with `pip install claude-code-acp`) spawns a stdio JSON-RPC server compatible with any ACP client. It supports the full ACP spec: images, file edits, tool calls, streaming text, etc.. Authentication is handled by the official Claude CLI (users must first run `claude /login`); no API key is required. The adapter even implements advanced features like subagent sessions, permission requests, goals, and custom slash commands. It can also serve the ACP draft v2 protocol (via `CLAUDE_AGENT_ACP_EXPERIMENTAL_V2=1`). A notable point: Claude’s CLI has limited tool gating (e.g. it cannot run its own `/mcp reconnect`), so the adapter works around this by using the SDK’s control API to manage MCP servers. Integration steps: install and authenticate `claude`, then run `claude-code-acp` and configure your editor (e.g. Zed settings) to launch it as an ACP agent.

- **Google Antigravity CLI**: Google’s new agent CLI (successor to Gemini CLI) is **not documented as ACP-compatible**. It is a standalone TUI agent interface (written in Go) that shares a core agent engine with the Antigravity 2.0 GUI. It communicates with Google’s Antigravity harness (likely via gRPC to a backend service) rather than over stdio. Official docs describe it as a terminal UI for running agents, with features like subagents and slash commands. The CLI is installed via a platform-specific script and uses Google authentication (e.g. `gcloud` login or SSO). **No ACP mode or endpoints are mentioned**: there is no `agy acp` command or JSON-RPC interface in the public docs or repo. For now, ACP integration is unspecified for Antigravity; one might need to host the Antigravity agent harness and write a custom ACP adapter.

**Compatibility Matrix:** All ACP-compliant agents (above) share a common JSON-RPC format, so any ACP-supporting editor can interoperate with any agent that implements the spec. For example, Zed, Neovim, JetBrains, or a custom Python/TypeScript ACP client can connect to Codex, Cursor, Grok, or Claude Code as above. The matrix below highlights cross-support:

|                    | **VSCode/Neovim** | **JetBrains IDEs** | **Zed Editor** | **Emacs+ACP** |
|--------------------|-------------------|--------------------|----------------|---------------|
| **Codex (codex-acp)**   | ✔ (spawn via npx)   | ✔ (ACP plugin)     | ✔ (spaawn CLI) | ✔ (generic ACP) |
| **Cursor**         | ✔ (spawn with agent acp) | ✔ (ACP plugin)     | ✔ (Zed ACP config) | ✔ |
| **Grok**           | ✔ (spawn `grok agent`)  | ✔ (ACP plugin)     | ✔ (custom agent server entry) | ✔ |
| **Claude Code**    | ✔ (spawn `claude-code-acp`) | ✔ (ACP plugin)     | ✔ (Zed supports it by settings) | ✔ |
| **Antigravity**    | ✘ (no ACP server)  | ✘                | ✘              | ✘  |

The checkmarks indicate that in principle the agent can be invoked as an ACP server for that editor. Antigravity CLI itself **cannot** be used as an ACP agent in editors. (Editors could, however, connect to remote Google agents via other means, but that is outside standard ACP today.)

*Sources:* Official documentation and code for ACP and each agent (cited above). When information was unavailable (e.g. no public ACP support for Antigravity), we have noted it explicitly. All details are drawn from the agents’ own repos/docs or the ACP spec.
